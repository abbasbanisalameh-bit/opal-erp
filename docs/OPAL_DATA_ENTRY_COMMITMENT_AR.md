# التزام OPAL ERP: توحيد مداخل البيانات

## القاعدة الملزمة

لا تدخل أي معلومة تشغيلية إلى OPAL ERP إلا من خلال شاشة رسمية داخل موقع OPAL وبطريقة واحدة محددة لكل معلومة. لا تستخدم لوحة Django Admin لإدخال بيانات المدرسة أو تعديلها.

## التطبيق

- لكل كيان تشغيلي شاشة إدخال رسمية واحدة فقط.
- الشاشات القديمة تتحول إلى عرض أو تعديل أو تحويل إلى الشاشة الرسمية؛ ولا تنشئ سجلًا جديدًا من مسار ثانٍ.
- لا تُنشأ نماذج مكررة ولا تُكرر البيانات لمجرد وجود أكثر من وحدة تعرضها.
- لوحة Django Admin محجوبة عن التشغيل اليومي، وتبقى عمليات الصيانة الفنية عبر آليات آمنة ومحددة فقط.

## الاستثناء: OpenEMIS

يجوز استيراد معلومات الطلبة من OpenEMIS عند تفعيل الربط الرسمي. عند حفظ الطالب داخل OPAL:

1. يبحث النظام أولًا عن الطالب الموجود باستخدام المعرّفات الرسمية المتاحة.
2. يدمج البيانات المستوردة مع سجل `students.Student` الرسمي القائم.
3. لا ينشئ سجل طالب ثانٍ عند وجود تطابق موثوق.
4. تبقى بيانات OPAL التشغيلية، مثل التسجيل والرسوم والأسرة والحضور، محفوظة ومتكاملة مع البيانات المستوردة.

`students.Student` هو نموذج الطالب الرسمي الوحيد في جميع الحالات.
