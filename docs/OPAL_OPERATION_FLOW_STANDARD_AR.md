# معيار سير العمليات الموحد في OPAL ERP

## القاعدة الحاكمة

كل عملية تشغيلية لها **شاشة رسمية واحدة** ومصدر بيانات واحد. يجوز إظهار اختصار للعملية داخل بطاقة الطالب أو المعلم أو الأسرة، لكن الاختصار يجب أن يقود إلى الشاشة الرسمية نفسها، ولا يجوز أن ينشئ نموذجًا ثانيًا أو منطق حفظ مكررًا.

لا تُحذف أي ميزة قائمة ولا تُخفى من أجل تبسيط الواجهة. التبسيط يكون بتنظيمها داخل دليل العمليات، وتحديد موضعها الرسمي، وتحويل الروابط القديمة إلى المسار الرسمي عند وجود تكرار حقيقي.

## دورات التشغيل الأساسية

1. **تهيئة العام الدراسي:** إعدادات المدرسة ← الفروع ← العام الحالي ← الفصل الحالي ← الصفوف والشعب ← المواد ← الخطة الدراسية.
2. **المعلم والجدول:** ملف المعلم وحسابه ← التكليف ← إعداد الحصص ← منشئ الجدول ← الجدول النهائي.
3. **التسجيل:** المرشح اختياريًا ← التسجيل الذكي ← `students.Student` ← القيد ← الأسرة وحساب ولي الأمر ← الرسم والدفعة والإيصال ← بطاقة الطالب 360.
4. **الرسوم:** فئات الرسوم ← رسوم الطلاب ← التسديد الموحد للأفراد أو الإخوة ← أرشيف الإيصالات ← الأقساط والخصومات ← الكشف الشهري ← الإغلاق المالي.
5. **التشغيل اليومي:** الحضور ← الواجبات ← الامتحانات ← إدخال المعلم للعلامات ← مراجعة الإدارة ونشر النتائج ← عرضها لولي الأمر.
6. **التواصل والرقابة:** شكوى أو اقتراح وتقييمان ← معالجة الإدارة ← تعميم أو تنبيه أو إعلان ← إشعار المستخدم ← التقارير وسجل العمليات.
7. **نهاية العام:** اكتمال النتائج ← إغلاق مالي ← إغلاق أكاديمي ← الترفيع أو التخرج ← تهيئة العام الجديد.

## مصادر الحقيقة

- الطالب: `students.Student`.
- الحالة الأكاديمية للطالب: `academics.Enrollment`.
- الأسرة وحساب ولي الأمر: `parent_portal.Family` وروابط الأبناء.
- ارتباط المعلم بالمادة والشعبة: `teachers.TeacherAssignment`.
- الخطة الأسبوعية: `curriculum.Curriculum`.
- الحصص: `timetable.TimetableEntry`.
- الرسوم والدفعات والإيصالات: نماذج الرسوم المدرسية، مع شاشة التسديد الموحدة في `admissions`.
- العلامات: `exams.StudentMark`، والإدخال من تكليف المعلم فقط.
- التتبع: سجل عمليات OPAL، لا سجلات جانبية مكررة.

## فحص التكامل

من الواجهة: **الإعدادات ← دليل العمليات الموحد**.

من الطرفية:

```bash
python manage.py audit_operation_flow --allow-issues
python manage.py audit_operation_flow --json --allow-issues
```

قبل التشغيل الحقيقي يجب تشغيل الأمر من دون `--allow-issues`، ولا يعتمد النظام للإنتاج حتى ينجح الفحص أو تُوثق الاستثناءات المقبولة.

## سياسة الروابط القديمة

- إذا كانت الوظيفة مكررة فعلًا، يبقى الرابط القديم للتوافق لكنه يحول إلى الشاشة الرسمية.
- إذا كانت الوظيفة مستقلة وموجودة في النظام، تبقى ظاهرة وقابلة للاستخدام في موضع واحد، ولا تُحوّل إلى وظيفة مختلفة.
- إجراءات السجل المحدد، مثل تعديل طالب أو إلغاء رسم، تبدأ من شاشة القائمة أو بطاقة 360 الرسمية لذلك السجل.
