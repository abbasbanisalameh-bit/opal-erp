# دليل جاهزية التشغيل الفعلي — OPAL ERP

## الهدف

هذا الفحص يحدد هل بيئة OPAL جاهزة لاستقبال البيانات الحقيقية. لا يحذف بيانات، ولا يغيّر قاعدة البيانات، ولا ينفذ تصفيرًا تلقائيًا.

## أمر الفحص

```bash
python manage.py audit_production_readiness --output docs/production/production_readiness.json
```

للاعتماد الصارم بحيث تمنع التحذيرات أيضًا:

```bash
python manage.py audit_production_readiness --strict --output docs/production/production_readiness.json
```

## قبل إدخال البيانات الحقيقية

1. انسخ القيم المطلوبة من `.env.example` إلى إعدادات خادم التشغيل، ثم اضبط `OPAL_SECRET_KEY` بقيمة سرية إنتاجية لا يعرفها أحد خارج مدير النظام.
2. إبقاء `OPAL_DEBUG=False`.
3. تحديد نطاق الموقع في `OPAL_ALLOWED_HOSTS`.
4. التأكد من HTTPS ثم تفعيل إعدادات HSTS عند الاستقرار.
5. تشغيل `python manage.py check` و`python manage.py migrate`.
6. إنشاء نسخة احتياطية خارجية من الكود والإعدادات وقاعدة البيانات.
7. مراجعة الحسابات الإدارية وتغيير كلمات المرور المؤقتة.
8. مراجعة تقرير البيانات التجريبية قبل أي حذف يدوي مقصود.

## ما تغير في Update 108

- مركز التطوير خاص بمدير النظام الأعلى؛ لا يعتمد على ظهور الرابط في القائمة فقط.
- قبل استعادة أي تحديث، ينشئ مركز التحديث نقطة أمان خاصة لقاعدة SQLite. إذا فشل الفحص أو الترحيل، يعيد الكود وقاعدة البيانات تلقائيًا إلى حالتهما السابقة، من دون استخدام `--fake`.
- النسخ اليدوية في مركز التحديث تبقى نسخ كود فقط. لا تغني نقطة الأمان الداخلية عن نسخة احتياطية خارجية مستقلة.
- يفحص مركز التحديث الآن بالترتيب: `check` ثم `makemigrations --check` ثم `migrate` ثم `collectstatic` ثم `check` أخيرًا.

## قاعدة الأمان

لا يُحذف أي سجل تجريبي تلقائيًا. حذف البيانات التجريبية يتم فقط بأمر منفصل وصريح وبعد نسخة احتياطية، ولا يدخل ضمن تحديث 76.
